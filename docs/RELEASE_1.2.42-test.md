## 修复范围

- 配置写入在同一锁内读取最新状态、修改副本并持久化，再发布新状态；隐私、中间件、模型暴露、路由组以及相关供应商设置不再改写已发布的旧对象。
- 续期使用账号级凭据代际与生命周期，普通设置、签到记录及其他账号更新不再误判为当前账号被替换。删除后重新添加、停用后再启用、身份/凭据替换、服务退役仍拒绝迟到结果；不重放已消费或结果未知的刷新凭据。
- 完整配置接口增加乐观并发校验，拒绝用过期快照覆盖后来新增、删除、停用或已续期的账号。
- 独立Key兼容字符串和对象，保留enabled/off、同值去重与停用账号镜像保护。WorkBuddy/WorkBuddy-AI及ZCode零账号独立Key均完成导入→实际路由→实际选中Key回归；ZCode赠送JWT与付费Key保持隔离。
- 面板流式测试防重复提交，提供取消入口；模型/供应商切换、离页、超时和页面销毁释放本页面拥有的连接，晚回调不能覆盖新请求。定时后台刷新同一供应商不会误取消正在进行的测试。
- 原生桥普通响应使用严格HTTP分帧、UTF-8校验、8 MiB上限和总读取期限；授权普通响应亦增加大小限制及失败关闭。SSE保持增量读取，不把整条推理流缓冲到内存，不修改模型输出参数。

## 完整配置接口兼容说明

1. 先通过管理鉴权执行 `GET /api/config`，取得配置和顶层 `revision`。
2. `POST /api/config` 时原样携带该 `revision`，或用顶层 `expectedRevision` 指定它。两者同时提供时必须一致。
3. 无版本或版本已过期返回409，客户端应重新读取后让用户确认修改，不盲目重发整个旧配置。
4. 版本标记不保存进配置文件；服务重启后旧版本失效。凭据引用校验、管理鉴权及网关口令/首次设置等专用接口保护仍保留。
5. 原有供应商开关、Key、路由、隐私等专用接口不需要改用整份配置POST。
